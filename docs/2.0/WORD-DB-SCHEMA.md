# `words_ka.db` — contract for the app

The shipped database. **This schema is frozen** — build against it now; only the
number of rows changes as review finishes.

- **Read-only.** Bundle it; never write to it. Player state (seen cards, scores,
  settings) belongs in your own store, keyed by `words.id`.
- **`words.id` is stable forever.** IDs are never reused or renumbered, so
  caching "already seen card 4711" is safe across content updates.
- Current size: **0.41 MB / 2,964 words**. Expect **~1 MB / ~6,000 words** when
  review is done. Bundle it directly — no download, works offline.

Generated by `scripts/export_app_db.py` from the working database. Only
`status='approved'` words are exported, so a word rejected in review can never
reach the app.

## Tables

```sql
words (
  id             INTEGER PRIMARY KEY,   -- stable across releases
  lemma          TEXT NOT NULL,         -- the card text, Georgian Mkhedruli
  pos            TEXT NOT NULL,         -- 'noun' | 'verb' | 'adj' | 'propn'
  difficulty     INTEGER,               -- 1 easy .. 5 hard
  concreteness   INTEGER,               -- 1 abstract .. 5 physical object
  familiarity    INTEGER,               -- 1 rare .. 5 everyone knows it
  is_describable INTEGER NOT NULL,      -- Alias: always 1 today
  is_actable     INTEGER,               -- Charades: 1 if it can be mimed
  is_family_safe INTEGER NOT NULL       -- always 1 today; an adult pack would use 0
)

categories (
  id         INTEGER PRIMARY KEY,
  parent_id  INTEGER,                   -- NULL = top-level branch (15 of them)
  slug       TEXT NOT NULL UNIQUE,      -- 'food_georgian' — use for code, never display
  name_ka    TEXT NOT NULL,             -- 'ქართული სამზარეულო' — show this
  name_en    TEXT,                      -- 'Georgian cuisine'
  sort_order INTEGER NOT NULL
)

word_categories (word_id, category_id)  -- MANY-TO-MANY, see the warning below

taboo_terms (word_id, position, term)   -- empty until the Taboo mode ships

meta (key, value)                       -- schema_version, content_version,
                                        -- language, word_count
```

## Two things that will bite you if you assume otherwise

**A word belongs to several categories.** 4,275 links for 2,964 words. თესლი
(seed) is in agriculture, ecology, garden and plant_parts. Any query joining
`word_categories` without a `DISTINCT` or a single-category filter returns the
same word more than once.

**`difficulty` is not the same as `familiarity`.** "Photosynthesis" is familiar
*and* hard to describe. For a difficulty selector, `difficulty` is the right
column; for "does the player know this word at all", use `familiarity`.

## Queries you will actually need

Drawing a round — one category, capped difficulty, no duplicates:

```sql
SELECT DISTINCT w.id, w.lemma
FROM words w
JOIN word_categories wc ON wc.word_id = w.id
WHERE wc.category_id = ?1 AND w.difficulty <= ?2
ORDER BY RANDOM() LIMIT ?3;
```

Mixed round across the whole deck:

```sql
SELECT id, lemma FROM words
WHERE difficulty BETWEEN ?1 AND ?2
ORDER BY RANDOM() LIMIT ?3;
```

Charades round — actable words only:

```sql
SELECT id, lemma FROM words
WHERE is_actable = 1 AND difficulty <= ?1
ORDER BY RANDOM() LIMIT ?2;
```

Category picker, grouped under its branch, hiding empties:

```sql
SELECT p.name_ka AS branch, c.id, c.name_ka, COUNT(DISTINCT wc.word_id) AS n
FROM categories c
JOIN categories p ON p.id = c.parent_id
JOIN word_categories wc ON wc.category_id = c.id
GROUP BY c.id
HAVING n > 0
ORDER BY p.sort_order, c.sort_order;
```

Excluding cards already seen this session — pass the seen IDs, or keep a
`NOT IN (SELECT id FROM seen)` against your own table:

```sql
SELECT id, lemma FROM words
WHERE difficulty <= ?1 AND id NOT IN (SELECT value FROM json_each(?2))
ORDER BY RANDOM() LIMIT ?3;
```

`ORDER BY RANDOM()` scans the candidate set. At 6,000 rows that is well under a
millisecond — do not build a shuffle table for it.

## Difficulty tiers, if you want named modes

`difficulty` clusters around 2–3. A three-tier selector maps cleanly:

| Mode | Filter |
|---|---|
| Easy / family | `difficulty <= 2` |
| Normal | `difficulty <= 3` |
| Hard | `difficulty >= 4` |

Check `SELECT difficulty, COUNT(*) FROM words GROUP BY difficulty` against the
current file before hard-coding tier sizes.

## Content updates

`meta.content_version` is a `YYYYMMDD` stamp. Compare it to decide whether a
newly bundled or downloaded database is newer than the one you have.

Because `words.id` is stable, an update is safe to drop in: previously seen
cards stay correct, and any card you cached by id still resolves. Words removed
in a later revision simply stop appearing in query results — handle a missing id
by skipping it, not by crashing.

## What is still coming

- **More words.** 2,964 → roughly 6,000 as review completes. Nothing else changes.
- **`taboo_terms`** stays empty until the Taboo mode is built. The table exists
  so adding it later needs no migration.
- **`is_drawable`** is deliberately absent — Pictionary is not in v1. It would
  arrive as a new column with a `schema_version` bump.
- **Other languages** would ship as a separate file (`words_en.db`) with this
  same schema, not as extra rows here.
